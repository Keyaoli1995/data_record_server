# TCP 原始数据采集器设计

## 目标

为未知协议的 TCP 数据回传 App 提供一个可长期运行的接收服务。服务监听服务器公网端口 `30050`，不丢弃或修改收到的字节，并为后续协议逆向分析保留足够的连接和时间信息。

## 范围

第一版只负责采集、持久化和诊断，不解析业务字段、不向设备发送业务 ACK、不提供 Web 页面或数据库查询功能。

## 架构

服务使用 Python 标准库实现 TCP 服务器，以 Docker Compose 运行。容器对外发布 `30050/TCP`，接收器为每个客户端连接创建一个原始二进制文件，并追加一个 JSONL 事件日志。数据目录由 Docker 挂载到宿主机，因此容器重启、升级或重新创建不会删除已采集数据。

```text
App/设备 -- TCP --> 8.134.210.73:30050
                         |
                         v
                  Docker 容器中的接收器
                    |              |
                    v              v
             connections/*.bin   events.jsonl
```

## 配置

服务从环境变量读取配置：

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `TCP_PORT` | `30050` | TCP 监听端口 |
| `DATA_DIR` | `/data` | 容器内持久化数据目录 |
| `READ_BUFFER_BYTES` | `4096` | 单次读取的最大字节数 |

Docker Compose 将宿主机项目下的 `data/` 目录挂载为容器内 `/data`，并设置 `restart: unless-stopped`。

## 数据留存

每个 TCP 连接生成一个文件：

```text
data/connections/20260810T160001.123456Z_1.2.3.4_51822.bin
```

文件内容按接收顺序直接追加 TCP 字节；不添加分隔符、换行或编码转换。

事件文件为 `data/events.jsonl`。每行是一个 JSON 对象，包含：

- `connected`：UTC 时间、客户端 IP、客户端端口和原始文件名；
- `received`：UTC 时间、原始文件名、本次读取的字节数和十六进制字符串；
- `disconnected`：UTC 时间、原始文件名和此连接累计字节数；
- `error`：UTC 时间、原始文件名、错误类型和错误文本。

JSONL 只用来帮助定位和分析，`.bin` 文件才是原始数据的权威副本。

## 行为和错误处理

- 服务监听所有 IPv4 网络接口，允许设备通过公网连接。
- 每个客户端连接独立处理；一个连接异常或断开不会终止服务或影响其他连接。
- 首版不发送应用层数据。TCP 三次握手和内核 ACK 仍正常工作，但若设备协议要求业务 ACK，采集的原始报文可用于后续补充该功能。
- 创建数据目录和写入事件失败时记录服务错误；连接结束时关闭文件句柄。
- 进程收到停止信号时停止接收新连接，并关闭监听 socket。

## 安全与运维

- 阿里云安全组需要放行 TCP `30050`；当前已通过临时监听验证公网到该端口的连通性。
- 原始报文可能包含设备标识或敏感信息，`data/` 不提交到 Git。
- 服务通过 Docker Compose 的 `restart: unless-stopped` 在异常退出或服务器重启后恢复。
- 运行状态使用 `docker compose ps`、`docker compose logs` 查看；原始数据在宿主机 `data/` 查看。

## 测试策略

使用 Python `unittest`，不引入第三方运行时依赖。测试先于实现编写，并验证：

1. TCP 客户端发送的多个字节块按顺序完整写入单个 `.bin` 文件；
2. `events.jsonl` 依次包含连接、接收和断开事件，并记录正确的字节数与十六进制内容；
3. 一个客户端断开后，服务仍可接受另一个客户端；
4. 端口和数据目录能够通过配置修改。

## 验收标准

在服务器上执行 `docker compose up -d --build` 后，服务监听 `30050/TCP`。将 App 配置为 `8.134.210.73:30050` 并发送数据后，项目的 `data/connections/` 中出现非空 `.bin` 文件，`data/events.jsonl` 中能找到相同文件名对应的事件记录。容器重启后，已写入数据仍存在且服务自动恢复监听。
