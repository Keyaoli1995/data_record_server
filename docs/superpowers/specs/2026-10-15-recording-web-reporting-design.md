# 录制服务三阶段 Web 上报设计

日期：2026-10-15。状态：用户已批准，已完成本地实现；未部署到远端。

## 1. 依据、范围和确认状态

依据《人工耙沙录制轨迹 Web 端接口控制文档（ICD）》第 4.1 节，以及本轮用户确认。ICD 来源：`E:/Work/Document/08_定位棒/人工耙沙轨迹_web端发入/人工耙沙录制轨迹Web端接口控制文档ICD.md`。

**已确认：一份录制文件对应一个录制任务。** 首次有效记录产生文件和新任务 ID；沿用现有设备级会话，默认 30 秒无有效记录关闭文件；关闭即本地任务结束；之后收到数据创建新文件、新任务。TCP 重连未达到会话超时则继续原文件。一个任务的文件顺序恒为 1。

Web 需确认：唯一文件正常结束并校验为 READY 后，将所属任务标记 FINISHED。此项是联调前提，不能假设 Web 已实现。

本次负责录制、统计、创建/更新/关闭通知、可靠补发和作业地时区识别；不改解析脚本，不实现 Web 索引、实时流、地图管理，不在本次文档任务中部署或推送。

更新周期、自动时区识别及恢复策略已按用户授权实施；人工时区覆盖和可选 points 不在首版范围。接口内网地址由 Web 提供；新版 ICD 的三个录制上报接口免登录鉴权。未核验实际接口时可以完成模拟测试，但不得宣称真实联调通过。

## 2. 现状与改动位置

- `protocol.py`：按行校验 JSON 和 deviceId，保留原始字节；尚无作业时区字段协议。
- `storage.py`：设备级文件与会话、追加后 flush、超时关闭、保留策略。当前无 Web 上报功能。
- `server.py`：并发 TCP 接入、定期会话回收、优雅停机。
- `config.py`、`compose.yaml`、`Dockerfile`：配置与容器部署，Python 3.12。
- 现有测试使用 unittest，继续沿用，可通过 pytest 执行。

保留现有原始数据格式、命名和存储目录。增加独立持久化通知模块，不在 TCP 处理线程执行 HTTP 或地理查询。原始数据缺少 GPS/坐标不改变已有录制接收规则，仅影响统计、时区和通知状态。

## 3. 任务和文件身份

创建文件时生成并持久化两项独立 UUID 标识：`rakingRecordingTaskId`、`fileKey`，使用 URL 安全字符串。重试和重启不得重新生成。SN 直接使用文件 deviceId，不推断机器人 SN。

创建请求中的 `sequence=1` 是文件在任务中的顺序；更新/结束中的 sequence 是该文件的通知版本，单独计数，不混用。更新从 1 递增，关闭使用新的更大序号。通知内容和幂等键一旦进入发送队列不可修改。

`storageUri` 使用文件相对 DATA_DIR 的 POSIX 路径，例如 `devices/device-BY80126B66/<原文件名>.jsonl`。Web/Worker 将此映射到各自挂载根目录；不发送绝对路径、账号或下载 URL。

## 4. 三阶段请求

所有路径相对已配置 Web 根地址，禁止重复追加 `/api`。

| 阶段 | 方法与路径 | 必填业务字段 |
| --- | --- | --- |
| 创建 | POST `/api/v2.4/manual-raking/recording-files/` | schemaVersion=1、rakingRecordingTaskId、fileKey、rakingLocatorSn、sequence=1、storageUri、openedAt |
| 更新 | PATCH `/api/v2.4/manual-raking/recording-files/{fileKey}/` | schemaVersion=1、sequence、updatedAt、recordCount、sizeBytes |
| 结束 | POST `/api/v2.4/manual-raking/recording-files/{fileKey}/closure/` | schemaVersion=1、sequence、closedAt、firstGpsTime、lastGpsTime、recordCount、sizeBytes、storageUri、sha256、closeReason |

各阶段可携带 timezone；创建可带 firstGpsTime；更新可带 lastGpsTime、lastReportedDataAt、currentLocation。首版建议上报最新位置，不上传可选 points 数组；因此不承诺完整实时轨迹历史，若 Web 需要该能力，应单独确认采样频率和可靠传输范围。

所有请求发送 `Content-Type: application/json` 和稳定的 `Idempotency-Key`，不发送 `X-Environment`。Web 环境由部署配置决定，本地 `WEB_ENVIRONMENT` 仅用于队列隔离。默认不发送 Authorization；可选网关鉴权通过独立配置注入，不在队列和日志中保存凭据。三个免鉴权接口仅允许内网调用，网络与反向代理负责来源限制。

成功需要 HTTP 成功、响应 JSON `code=0`、身份和状态与请求匹配。创建/更新只确认已接受；正常关闭需 READY，异常关闭需 ABORTED。HTTP 200 本身不是成功；未知响应保留通知并告警。

## 5. 数据统计与时间

`openedAt/updatedAt/closedAt` 是服务事件的 UTC ISO-8601 时间；`firstGpsTime/lastGpsTime` 是有效 gpsTime 的最小/最大值，Unix 毫秒。与 ICD 的“首末”表述统一后接入，不以服务器时间冒充 GPS 时间。

有效 gpsTime：整数且不是 bool，能表示约定范围内的 UTC 时间；缺失、非有限值、非法类型不参与统计。recordCount 统计实际落盘的所有记录，包括无有效 GPS 的记录；sizeBytes 和 SHA-256 以实际原始字节为准。关闭后由后台复核文件，不阻塞其他设备接收。

无有效 GPS 的文件保留原始数据，firstGpsTime/lastGpsTime 为 null，按 ABORTED 上报，不成为正常候选。无有效坐标但有有效 GPS 不应仅因缺时区而判失败。

关闭原因：空闲超时映射 IDLE_TIMEOUT；明确异常映射 ABORTED。正常服务停机原因建议增加 SERVER_SHUTDOWN，必须与 Web 枚举对齐；不能伪称设备关机或人员主动停止。未确认的枚举阻止真实联调，不影响本地测试契约。

## 6. 作业地时区方案（已批准自动识别）

### 6.1 推荐：由作业点经纬度离线查询 IANA 时区

数据已包含 `GNSSlat/GNSSlon`。使用 WGS84 坐标查询地理时区边界，得到 `Asia/Shanghai`、`America/Los_Angeles` 等 IANA 名称。服务器地区、服务器系统时区、IP、浏览器时区均不能作为作业地的推断依据。GNSS 的 UTC 时间也不包含作业地时区。

可选实现为 timezonefinder 离线边界查询；Python zoneinfo 用于校验名称及按实际日期处理 UTC 到当地时间转换。zoneinfo 本身不做经纬度查询。库和边界数据版本在实施时锁定并记录，评估镜像大小、许可证和冷启动内存，运行期间不请求第三方地理 API。

坐标质量建议使用明确的 GNSS 有效状态白名单，首版自动判定仅使用 `GNSSPosStat=4`（字符串或整数形式，代表含义须与现有解析器核对）、有限经纬度及合法范围。无效零占位坐标、非有限值不参与判定。候选点需时间递增；建议连续 3 个合格点覆盖至少 2 秒且查询结果一致后锁定。期间出现不同结果重新收集；该阈值是工程过滤，不代表测量精度保证。

创建时尚未确定则省略 timezone。确定后在下一次更新和结束通知携带相同值。整个任务锁定一次，不把尚未确认的候选发给 Web，避免首次上报即永久写错。后续位置跨时区或出现冲突，记录本地告警但不覆盖。首版任务时区代表录制起始稳定作业位置，不代表跨时区轨迹每个点的当地时间。

查询必须采用所选库提供的严格陆地边界判定，不能将海洋默认偏移或“最近时区”当作已确认作业地时区。边界附近、坐标不稳定、无有效定位或查不到时允许整次任务不携带 timezone，UTC 数据和文件上报继续工作。Web 显示“作业地时区未确定”，不得默认用服务器当地时间冒充作业时间。

### 6.2 可选兜底：明确的现场配置

可为 SN 配置“作业点 + IANA 时区 + 有效期”的人工核实记录，在新任务开始时读取快照，优先于自动识别。配置必须来自实际作业点，不能仅按国家或服务器环境生成；设备调往新场地时更新或失效。任务进行中不热修改已锁定时区。若坐标识别与人工配置冲突，告警供人员核查。

纯人工配置依赖维护，设备迁移容易遗忘；纯在线地理 API 增加网络依赖。本设计推荐离线自动识别为默认，现场配置作为受控覆盖；首版不实现人工覆盖功能，后续需独立确认配置的来源和维护方式。

### 6.3 夏令时与存储

始终保留 UTC 时间戳，timezone 只提供作业地规则。不要上报固定 `UTC-8` 替代 `America/Los_Angeles`。Web 使用实际记录日期和 IANA 时区转换，自动适配该日期对应的夏令时。

本地审计记录时区来源、确定所用坐标/时间、库和边界数据版本；这些扩展信息不加入 ICD 未约定的请求字段。无法识别不影响原始录制。

参考：[timezonefinder 官方用法](https://timezonefinder.readthedocs.io/en/latest/1_usage.html)、[Python zoneinfo](https://docs.python.org/3/library/zoneinfo.html)。

## 7. 可靠通知与恢复

推荐 SQLite 本地 outbox，位于 DATA_DIR 下独立目录。文件登记、阶段请求和重试状态持久化；后台发送器保证同一文件创建成功后才能发送更新/结束。一个文件的鉴权或数据错误不能堵塞其他文件。

建议更新周期 10 秒，可配置；只为有变化的数据建立更新。未生成正式请求前可合并统计快照；生成后的序列、幂等键和内容不可改。重试指数退避（起始 1 秒，上限 60 秒并加抖动），每次请求有限超时。网络错误、429、5xx 可重试；鉴权、参数、环境错误转人工处理状态，不丢弃。业务错误优先于 HTTP 状态，遵循服务端有效 Retry-After。

磁盘原文件与 SQLite 不是一个事务：登记待创建文件身份，再创建原文件，启动时核对两侧状态。追加后仅做必要本地统计；更新通知是快照而非每点事务。文件已关闭但关闭通知未入库的窗口，通过重启扫描已登记非终态记录、读取完整原文件重建关闭通知。实际尾部不完整或损坏，原文件保持不变并异常归档；不得静默截断修复。

仅本进程已登记的文件自动恢复，历史未登记文件需显式补录工具。任何重放必须保留原 fileKey/taskId；重启前仍活跃的文件不继续追加，核验后结束旧文件，新数据进入新任务。

Web 任务超时是远端终态：收到 TIMEOUT 不换 ID 重复上报旧文件，也不继续盲目重试。保存原始数据和通知，提供人工恢复记录。Web 必须提供针对延迟通知、历史完整文件的补录规则，否则无法保证长时间 Web 故障后自动恢复可选。

清理策略跳过正在录制、尚未完成通知或人工待处理的文件，并提供积压数量、最老等待时长和磁盘占用日志；长期积压需运维处置，不静默清除。磁盘不足必须明确告警，不能宣称录制和通知均成功。

## 8. 配置和启停

新增开关默认关闭；关闭时保持原行为。启用必须确认 Web 内网根地址、本地队列环境标识和存储根映射；鉴权配置为可选。生产 HTTPS 校验证书，不将鉴权头转发到重定向地址。无有效地理库时自动时区不可用应有明确告警，不能影响原始数据写入。

生命周期：初始化持久化队列和恢复记录 → 启动发送器 → TCP 接收 → 停机停止新接入并关闭文件 → 落盘最终通知 → 有界等待发送器退出。Web 不可达不无限阻塞停机，未发送记录留到下次启动。

## 9. 联调前的外部确认项

1. 唯一文件 READY 后所属任务进入 FINISHED；ABORTED 如何结束任务。
2. 各环境地址、服务鉴权方式、成功响应和错误码的正式契约。
3. 正常服务停机原因枚举、GPS 范围采用 min/max、time/coordinate 字段缺失处理。
4. Web 超时后的补录流程，以及同文件标识重试/修复 INVALID 的规则。
5. 时区推荐方案及人工覆盖范围；作业点位置质量判定；是否需要增量 points。
6. Web/Worker 共享只读原始存储映射、保留期和文件不可变保证。

## 10. 验收

模拟 Web 验证创建→更新→结束顺序、重复请求不重复入库、响应丢失重放、文件 SHA/字节数/记录数/GPS 范围一致、重启补发、多设备独立、错误隔离和停机恢复。用固定坐标测试时区识别，用固定 UTC 日期测试夏令时；既有录制、拒绝归档、保留和停机测试全部通过。真实 Web 验收需另行提供已部署接口。

## 11. 实现落地说明（2026-10-15）

- 当前采用后台增量扫描已落盘数据，TCP追加路径不执行HTTP和地理查询。关闭后完整复核原字节。
- 时区库使用 timezonefinder9.0.0，独立全球边界数据3.2026.4，tzdata2026.5；同时记录库和数据版本。全球28个代表地点及边界候选、海洋、夏令时等回归属于典型场景验证，不代表全球每个点均被验证。
- “严格陆地”要求在实现中具体为严格多边形包含并排除 Etc 海洋默认区。所用数据包含部分领海，重叠边界沿用数据集首个匹配；没有海岸线校验或距离边界置信区间。因此不能承诺所有边界附近结果一定为空，文档和 Web 提示应保留这项限制。
- Web ICD第6节业务错误包装为外层 code=40001、data.errorCode为稳定业务码；已按此格式识别终态，并支持HTTP错误时优先读取已知业务错误。
- 位置缺少高度或精度时不编造数值；当前上报位置可省略对应字段，需 Web 对 currentLocation 子字段的可空性确认。
- 停机在有限等待内尽量生成最终 outbox；大文件扫描超过预算时已持久化 CLOSED 意图，后台继续收尾，若进程被终止则重启恢复。不能为等待 Web 而无限阻塞停机。
- 运行配置、历史补录、积压查询和限制见 [接入与运维](../../web-reporting-operations.md)。
