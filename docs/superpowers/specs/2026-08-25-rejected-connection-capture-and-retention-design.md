# 拒绝记录连接归档与保留期设计

> 后续变更：设备归档与拒绝连接 `.bin` 的保留期已拆分，默认分别为 365 天与 30 天，并各自写入
> `device_retention_cleanup` / `connection_retention_cleanup` 事件。当前行为以
> [README.md](../../../README.md) 与 [CAPABILITIES.md](../../../CAPABILITIES.md) 为准；本文保留
> 当时单一 `RETENTION_DAYS` 的决策记录。

## 背景与目标

设备采集流以 JSON Lines（JSONL）为正常协议。当前服务会将有效记录按 `deviceId` 写入设备会话归档，并仅为无效记录写入 `record_rejected` 诊断事件。由于诊断事件不保存原始字节，现场无法复原导致解析失败的实际报文。

本设计在不改变有效数据归档规则的前提下，实现两项能力：

- 在同一条 TCP 连接中，将所有被拒绝记录的原始字节集中保存至一个诊断 `.bin` 文件；
- 仅保留最近 30 天的设备会话和诊断归档，并按服务器本地时间每日零点清理。

## 范围

### 包含

- 有效 JSONL 仍按现有 `deviceId` 会话规则写入 `data/devices/`。
- 每条 TCP 连接在第一次出现拒绝记录时，延迟创建一个 `data/connections/*.bin`；之后该连接的所有拒绝记录原始字节按接收顺序追加至此文件。
- 捕获所有 `record_rejected` 原因：`invalid_utf8`、`invalid_json`、`json_not_object`、`missing_device_id`、`device_id_changed`、`line_too_long`、`incomplete_line`。
- 在拒绝事件中关联诊断文件，并记录每次写入后的累计字节数。
- 诊断连接创建、关闭，以及每日清理均写入事件。
- 清理 `data/connections/*.bin` 与 `data/devices/**/*.jsonl`；删除空的设备目录。
- 以 Docker 容器可见的服务器本地时间作为每日零点，并让 Compose 只读挂载宿主机 `/etc/localtime`，使容器时间与宿主机一致。

### 不包含

- 不限制单个诊断 `.bin` 文件大小，也不做文件切分。
- 不自动删除 `data/events.jsonl`。
- 不修改客户端数据格式。

## 数据流

1. TCP 处理器将收到的字节交给 JSONL 流解析器。
2. 每条有效记录继续调用设备会话存储，追加至当前设备的 `.jsonl` 文件。
3. 每条拒绝记录都携带其原始字节：完整行保留原换行符；断开时未完成的数据和无换行超长数据保留已有全部字节。
4. 处理器按 TCP 连接惰性创建一个诊断连接记录器，并将步骤 3 的字节追加到该连接唯一的 `.bin` 文件。
5. 连接 EOF、socket 超时、超长行导致的连接关闭或服务器关闭时，关闭诊断记录器。没有拒绝记录的连接不会创建 `connections/` 文件。

诊断文件命名沿用旧版约定：

```text
data/connections/<UTC时间>_<安全客户端IP>_<端口>_<随机值>.bin
```

文件内容只包含被拒绝记录的原始字节，不含已成功归档的 JSONL 数据，也不添加自定义分隔符。

## 事件约定

- `rejected_connection_started`：第一次拒绝记录触发诊断文件创建；包含 `file`、客户端 IP 与端口。
- `record_rejected`：保留现有 `reason`，新增 `file`、`rejected_bytes`、`total_bytes`，其中 `total_bytes` 为对应诊断文件当前累计大小。
- `rejected_connection_closed`：诊断连接关闭；包含 `file`、`total_bytes` 与关闭原因（`eof`、`socket_timeout`、`line_too_long`、`server_shutdown` 或 `handler_error`）。
- `retention_cleanup`：每日或启动时清理结束；包含触发原因、删除文件数、释放字节数及失败数。

文件先成功写入并刷新，再写关联的 `record_rejected` 事件。若诊断文件操作失败，处理器记录服务端错误；不会把未持久化的数据伪装成已捕获。

## 保留期与清理

- 新增 `RETENTION_DAYS` 配置项，默认值为 `30`，必须为正整数。
- 服务启动后先执行一次清理；之后由服务循环在服务器本地日期跨越零点后的首次轮询执行一次。
- 过期判定使用文件最后修改时间：早于“本地当前时间减去 30 天”的文件删除。
- 当前正由设备会话或诊断连接记录器打开的文件加入活动集合，清理时跳过；关闭后将在下一轮清理中参与判断。
- 清理只遍历受控的 `data/devices/` 与 `data/connections/` 常规文件，不跟随符号链接；完成后删除空的 `device-*` 目录。

保留期控制长期磁盘占用；由于不设单连接容量上限，异常设备在单日内的持续大量输入仍可能占满磁盘，需通过运维监控和后续配额策略处理。

## 并发与安全性

- 每个 TCP 处理器只持有本连接的诊断记录器，多个连接互不共享文件。
- 事件写入继续使用现有全局锁；诊断文件由其所属处理线程顺序写入。
- 客户端 IP 仅用于文件名的安全表示；IPv6 的冒号替换为下划线，文件名再附加随机值避免冲突。
- 保留期清理不得删除活动文件，也不得跟随符号链接进入项目外路径。

## 测试与验收

- 解析器针对每种拒绝路径返回完全相同的原始字节。
- 一条连接中的有效、无效、有效记录：两条有效记录进入设备会话；无效字节仅进入一个诊断 `.bin`。
- 同一连接连续多个无效记录只生成一个 `.bin`，内容按发送顺序连接。
- 非 UTF-8、超长行、连接结束时未完成行均可在诊断文件中逐字节复原。
- 无拒绝记录时不创建 `connections/*.bin`。
- 连接超时、EOF、服务器关闭均关闭诊断文件并写关闭事件。
- 启动清理与跨本地午夜清理删除过期的 `.jsonl`/`.bin`，保留活动或未过期文件，并清理空设备目录。
- 部署配置确认容器时间与宿主机本地时间一致，文档说明默认 30 天保留策略。
