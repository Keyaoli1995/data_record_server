# 多连接录制数据规范化设计

## 目标

同一定位棒在网络重连、缓存补发或多个 TCP 连接并存时，保留每个连接的完整原始数据，同时在录制结束后生成按定位时间排列的规范 JSONL，供 Web 转换使用。

## 方案

- 保持现有 `devices/device-<SN>/<file>.jsonl` 路径不变。
- 录制期间继续向该主文件追加数据，供 Web 实时预览。
- 每个 TCP 连接首次提交有效记录时，另外创建一个连接原始 JSONL；后续该连接的所有有效记录只追加到自己的文件和主预览文件。
- 会话关闭时先关闭并同步所有连接原始文件，再执行归并：
  1. 解析各连接文件中的 JSONL；
  2. 仅保留 `opened_at - 5min <= gpsTime <= closed_at + 5min` 的记录；
  3. 将超出范围的记录写入隔离文件，不删除原始连接文件；
  4. 完全相同的 JSONL 行只保留一份；
  5. 按数值 `gpsTime` 升序稳定排序；
  6. 通过临时文件加 `os.replace` 原子替换主文件。
- 归并失败时保留已关闭的主预览文件，记录 `handler_error`，不向 Web 报告可用的 `READY` 文件。
- 关闭上报仍使用原主文件路径；Web 不需要知道连接原始文件和隔离文件。

## 数据目录

```text
data/
├── devices/device-<SN>/<file>.jsonl       # 录制中预览，关闭后变为规范 JSONL
├── connections/<session>_<ip>_<port>_*.jsonl  # 每连接原始数据
└── connections/quarantine/<session>.jsonl    # 会话范围外记录
```

连接原始文件保留现有连接归档清理机制；规范文件仍由 Web reporting 的保护路径保护。

## Web 兼容性

- 创建、周期更新、关闭上报接口和字段不变。
- `storageUri`、文件大小、记录数、时间范围和 SHA256 仍指向主文件；关闭上报只在原子替换完成后进入最终扫描。
- Web 录制中读取主文件，关闭后转换 Worker 读取同一路径，因此不需要 Web 端代码改动。

## 异常处理

- 连接原始文件写入失败：当前会话关闭为 `handler_error`，保留已写文件和事件记录。
- JSONL 时间字段无法解析：保留在原始文件并隔离，不进入规范文件。
- 时间超出会话范围：保留在原始文件，复制到隔离文件并记录数量。
- 完全重复记录：只在规范文件中去重，不修改原始连接文件。
- 进程重启：已有主文件和 Web durable outbox 的恢复行为保持不变；未完成的连接归档由下一次会话清理或人工检查处理。

## 验证指标

测试应验证：多连接数据完整落盘、归并后时间单调不下降、异常时间被隔离、完全重复行去重、主文件原子替换，以及 Web reporting 仍收到原路径的关闭通知。
